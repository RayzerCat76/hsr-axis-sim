What the replay validator is for:
A human will manually extract a small gameplay trace from a video. The replay JSON will contain initial state, chosen actions, forced RNG placeholders, and expected outcomes. The validator should replay those steps through the simulator and report whether the simulator matches the trace.

Effect deserialization:
Implement JSON-to-effect conversion for the existing generic effect primitives:
- DealDamage
- GainEnergy
- ConsumeEnergy
- GainSkillPoint
- ConsumeSkillPoint
- AdvanceAction
- DelayAction
- ChangeSpeed
- ImmediateAction
- GrantExtraTurn
- DoesNotEndTurn

For effects that inherit UnitEffect, support optional `target_ids` in JSON.
If `target_ids` are omitted, preserve existing default behavior.

Replay execution rules:
1. Build a `BattleState` from `initial_state`.
2. For each step:
   - Call `Timeline.next_turn(state)`.
   - Compare the selected actor to `expected_actor`.
   - Load the specified action from the replay `actions` map.
   - Override the action's `target_ids` with the step `target_ids` if provided.
   - Execute the action with the active `TurnContext`.
   - Compare expected values after execution.
3. Use numeric tolerance for float comparisons.
4. Return a structured result with all mismatches, not just the first mismatch.
5. Do not rely on pytest for normal validator operation. The validator should be callable from code.

Expected value checks:
Support checking:
- global_av
- skill_points
- extra_turn_stack
- each unit's:
  - current_av
  - speed
  - base_av
  - energy
  - hp
  - is_alive

Unknown fields:
- If the replay contains an unsupported expected field, record a mismatch saying the field is unsupported.
- If the replay references an unknown unit or action, raise or record a clear validation failure.
