Data model requirements:

A Unit should support base combat stats needed for MVP damage:
- atk
- def
- crit_rate
- crit_dmg
- dmg_bonus
- damage_reduction or vulnerability can be optional for now

Keep existing Unit construction backward compatible. Existing tests that instantiate `Unit("id", "Name", "ally", 100)` must still work.

Recommended default stats:
- atk: 100
- def: 0
- crit_rate: 0
- crit_dmg: 0.5
- dmg_bonus: 0

Buff stat modification:
Use existing `Buff.data` to hold stat mods. Keep it simple and explicit.

Recommended buff data shape:

```python
{
  "stat_mods": {
    "atk_pct": 0.20,
    "atk_flat": 50,
    "dmg_bonus": 0.30,
    "crit_rate": 0.10,
    "crit_dmg": 0.40
  }
}
```

Aggregation rules for MVP:
- effective_atk = base_atk * (1 + sum(atk_pct)) + sum(atk_flat)
- effective_dmg_bonus = base_dmg_bonus + sum(dmg_bonus)
- effective_crit_rate = base_crit_rate + sum(crit_rate)
- effective_crit_dmg = base_crit_dmg + sum(crit_dmg)

Damage formula MVP:

If `DealDamage` has fixed `amount`, preserve current behavior exactly.

If `DealDamage` has calculated mode, support fields like:
- `multiplier`
- `stat`: default `atk`
- `can_crit`: default True
- `damage_type`: optional string metadata

Recommended MVP formula:

```text
base_damage = effective_stat(attacker, stat) * multiplier
bonus_damage = base_damage * (1 + effective_dmg_bonus(attacker))
if can_crit and crit_result is true:
    final_damage = bonus_damage * (1 + effective_crit_dmg(attacker))
else:
    final_damage = bonus_damage
```

Do not add full HSR defense/resistance/toughness/break formula in this task. Add hooks/classes so it can be extended later, but keep the tested formula simple.

Forced RNG requirements:

Support deterministic crit behavior.

Replay step example:

```json
{
  "step": 1,
  "expected_actor": "dps",
  "action_id": "dps_skill",
  "target_ids": ["enemy_1"],
  "forced_rng": {
    "crit": true
  },
  "expect": {
    "units": {
      "enemy_1": {"hp": 7000}
    }
  }
}
```

Implementation guidance:
- Store forced RNG on `TurnContext`, or pass it cleanly into action/effect execution.
- If `forced_rng.crit` is present, use it.
- If `forced_rng.crit` is absent, use deterministic default behavior. For MVP, default can be `False` rather than random.
- Do not introduce nondeterministic random behavior yet.

Replay validator updates:
- It should read optional `forced_rng` from each step.
- It should pass that forced RNG into the action execution path.
- Existing replays without `forced_rng` must still pass.
