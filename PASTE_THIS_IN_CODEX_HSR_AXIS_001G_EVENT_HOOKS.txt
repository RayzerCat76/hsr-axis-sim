Core models:

Implement something equivalent to:

```python
@dataclass
class Event:
    type: str
    data: dict[str, Any]
```

Example event types for this MVP:

```text
action_started
action_finished
damage_dealt
unit_defeated
weakness_break
turn_started
turn_ended
```

Implement something equivalent to:

```python
@dataclass
class Trigger:
    id: str
    owner_id: str
    event_type: str
    condition: dict[str, Any]
    effects: list[Effect]
    max_triggers_per_action: int = 1
    enabled: bool = True
```

The trigger system may live on `BattleState.triggers`, on `Unit.triggers`, or both, but the replay schema must be clear and tests must cover loading it.

Condition MVP:

Support a small deterministic condition language. Do not build a huge rules engine.

Required condition types:

1. `always`
2. `event_actor_is_owner`
3. `event_source_is_owner`
4. `event_target_is_owner`
5. `event_killer_is_owner`
6. `field_equals`

Example:

```json
{
  "type": "event_killer_is_owner"
}
```

Example:

```json
{
  "type": "field_equals",
  "field": "target_id",
  "value": "enemy_1"
}
```

Event emission requirements:

`DealDamage` should emit:

- `damage_dealt` with at least:
  - `source_id`
  - `target_id`
  - `amount`
  - `damage_type`
  - `is_crit` if available from the damage calculation result

If damage reduces a target to 0 HP and the target was alive before the hit, emit:

- `unit_defeated` with at least:
  - `killer_id`
  - `target_id`

`DealToughnessDamage` / break logic should emit:

- `weakness_break` with at least:
  - `source_id`
  - `target_id`
  - `element`

Action / timeline lifecycle should emit at least:

- `action_started`
- `action_finished`

Optional but useful:

- `turn_started`
- `turn_ended`

Trigger execution requirements:

When an event is emitted, matching enabled triggers should run their effects deterministically.

Trigger effects should execute as if the trigger owner is the actor. This allows self-targeting effects to work through the existing `UnitEffect` default target resolution.

Example:

A trigger owned by `seele_like` with this effect:

```json
{
  "type": "GrantExtraTurn"
}
```

should grant an extra turn to `seele_like` because `GrantExtraTurn` with no explicit target defaults to the synthetic trigger action actor, i.e. the trigger owner.

Determinism and safety:

- Trigger ordering must be deterministic.
- Use insertion order or sort by trigger id, but document the chosen policy.
- Add a recursion / event processing limit to avoid infinite trigger loops.
- If the limit is exceeded, raise a clear `ValueError`.
- `max_triggers_per_action` should prevent the same trigger from firing too many times from one action.
- Existing tests and golden replays must still pass.

Replay Validator requirements:

Extend replay loading so initial state can include triggers.

Accept either top-level initial triggers:

```json
"initial_state": {
  "triggers": [ ... ]
}
```

or unit-owned triggers:

```json
"units": [
  {
    "id": "seele_like",
    "name": "Seele-like Unit",
    "team": "ally",
    "base_speed": 100,
    "triggers": [ ... ]
  }
]
```

Choose one primary schema and document it. Supporting both is optional.

The replay validator should also be able to check at least:

```json
"expect": {
  "extra_turn_stack": ["seele_like"],
  "logs_contains": ["trigger:on_kill_extra_turn"]
}
```

If you add `logs_contains`, keep it generic and tested.
