Goal:
Add a deterministic MVP for enemy action selection.

The simulator must be able to answer:
1. When an enemy gets a normal turn, which skill should it use?
2. Which target should the enemy choose?
3. Can enemy action patterns advance deterministically across turns?
4. Can replay validation omit a manual skill_id for an enemy turn and instead use the enemy AI policy?

Scope:
This task is only an MVP for deterministic enemy action patterns. It is not AI search, not full HSR enemy scripting, and not random enemy behavior unless forced by replay data.

Required behavior:

1. Add an enemy AI module

Create a new module such as:

```text
hsr_axis_sim/sim/enemy_ai.py
```

Implement data structures similar to:

```python
@dataclass
class EnemyPatternStep:
    skill_id: str
    target_strategy: str = "first_legal"
    target_ids: list[str] | None = None

@dataclass
class EnemyAIPlan:
    pattern: list[EnemyPatternStep]
    repeat: bool = True
```

You may adjust names, but keep the design simple, typed, and deterministic.

2. Add enemy AI schema support

Extend the existing data schema so a character JSON may optionally include:

```json
"enemy_ai": {
  "repeat": true,
  "pattern": [
    {"skill_id": "basic", "target_strategy": "first_legal"},
    {"skill_id": "skill", "target_strategy": "lowest_hp_legal"}
  ]
}
```

Rules:
- Existing character JSON files without `enemy_ai` must continue loading unchanged.
- Enemy AI should be optional.
- Validate that pattern is non-empty if `enemy_ai` exists.
- Validate that each pattern step has `skill_id`.
- If possible, validate pattern skill IDs against the character's skills.

3. Store enemy AI plans and cursors in BattleState

Extend `BattleState` with fields similar to:

```python
enemy_ai_plans: dict[str, EnemyAIPlan] = field(default_factory=dict)
enemy_ai_cursors: dict[str, int] = field(default_factory=dict)
```

Rules:
- Cursor is per unit instance, not per character template.
- Building state from data-loaded team files should attach enemy AI plans for units whose character has `enemy_ai`.
- Existing tests and replay files must not break.

4. Implement target strategies

Implement deterministic target strategy resolution.

Supported MVP strategies:

```text
first_legal
last_legal
lowest_hp_legal
highest_hp_legal
explicit
forced_rng_target
```

Definitions:
- `first_legal`: choose the first group from existing `legal_target_groups`.
- `last_legal`: choose the last group from existing `legal_target_groups`.
- `lowest_hp_legal`: among single-target legal groups, choose the live target with lowest HP.
- `highest_hp_legal`: among single-target legal groups, choose the live target with highest HP.
- `explicit`: use `target_ids` from the pattern step, then validate with existing target legality.
- `forced_rng_target`: use `forced_rng["enemy_target_id"]` or `forced_rng["target_id"]`, then validate with existing target legality.

Rules:
- Always use the skill's `target_type` and existing target legality.
- Dead targets must be excluded or rejected.
- If no legal target exists, raise a clear error.
- For all-target or none-target skills, strategies should resolve to `[]` via existing target legality.
- Do not invent a new target legality system.

5. Implement enemy action choice

Implement a function similar to:

```python
def choose_enemy_action(
    state: BattleState,
    skill_lookup: dict[str, dict[str, SkillSpec]],
    actor_id: str,
    forced_rng: dict | None = None,
) -> ActionChoice:
    ...
```

Rules:
- Actor must exist.
- Actor should be alive.
- Actor should have an enemy AI plan.
- Use `state.enemy_ai_cursors[actor_id]` to pick the current pattern step.
- If `repeat=True`, wrap around the pattern.
- If `repeat=False` and cursor exceeds pattern length, use the final step or raise a clear error; choose one behavior and document it.
- Use existing affordability checks where applicable.
- Use existing `action_from_skill(..., validate_targets=True)`.
- The choice function must not mutate state.

6. Implement enemy action execution helper

Implement a helper similar to:

```python
def execute_enemy_ai_action(
    state: BattleState,
    skill_lookup: dict[str, dict[str, SkillSpec]],
    actor_id: str,
    turn_context: TurnContext,
    forced_rng: dict | None = None,
) -> ActionChoice:
    ...
```

Rules:
- `turn_context.actor_id` must match `actor_id`.
- Choose the enemy action.
- Execute it using the existing `Action.execute` pathway.
- Increment the actor's enemy AI cursor only after successful execution.
- If execution fails, cursor must not advance.
- Normal turn semantics must remain normal: this is not an interrupt and not an extra turn.

Replay validation should support enemy AI execution for normal steps.

Add an optional step field:

```json

  "forced_rng": {"enemy_target_id": "seele_like"},

```

Rules:
- For normal steps with `use_enemy_ai: true`, Replay Validator should call `Timeline.next_turn(state)` as usual, then execute the enemy AI action.
- Actor must match `expected_actor` if provided.
- `use_enemy_ai` should only be allowed for normal steps, not interrupt steps.
- If a manual `skill_id` or `action_id` is present, existing behavior should remain unchanged.
- Existing replay files must keep passing unchanged.
