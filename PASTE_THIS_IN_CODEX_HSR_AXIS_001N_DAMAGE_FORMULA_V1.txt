Formula V1 requirements:

1. Preserve fixed damage compatibility
   - `DealDamage(amount=...)` must still subtract exactly that amount.
   - Existing fixed-damage golden replays must continue to pass.

2. Add a structured calculated damage pipeline
   Introduce a formula close to:

   base_damage = scaling_stat_value * multiplier + flat_damage
   after_bonus = base_damage * (1 + damage_bonus)
   after_crit = after_bonus * crit_multiplier
   after_defense = after_crit * defense_multiplier
   after_resistance = after_defense * resistance_multiplier
   final_damage = after_resistance * (1 + vulnerability)

   This is still an MVP formula, not a claim of full official HSR accuracy.

3. DamageSpec should support at least:
   - multiplier: float
   - stat: string, default "atk"
   - flat_damage: float, default 0
   - can_crit: bool, default true
   - damage_type: optional string
   - element: optional string
   - damage_bonus_key: optional string
   - defense_ignore: float, default 0
   - resistance_penetration: float, default 0
   - vulnerability: float, default 0

4. Effective attacker stats should support at least:
   - atk
   - defense
   - crit_rate
   - crit_dmg
   - dmg_bonus
   - element-specific dmg bonus, e.g. `quantum_dmg_bonus`, `wind_dmg_bonus`
   - type-specific dmg bonus, e.g. `skill_dmg_bonus`, `ultimate_dmg_bonus`, `basic_dmg_bonus`, `followup_dmg_bonus`

5. Effective target stats should support at least:
   - defense
   - damage_resistance by element, e.g. `quantum_res`, `wind_res`, or generic `all_res`
   - vulnerability / damage taken increase
   - defense reduction from debuffs

6. Buff/debuff stat_mods should remain the interface
   Existing buff data should still work:

   ```json
   {
     "stat_mods": {
       "atk_pct": 0.2,
       "crit_dmg": 0.3,
       "dmg_bonus": 0.5
     }
   }
   ```

   Add support for new stat_mod keys such as:
   - `def_reduction`
   - `def_ignore`
   - `all_res_pen`
   - `<element>_res_pen`
   - `vulnerability`
   - `<element>_dmg_bonus`
   - `<damage_type>_dmg_bonus`

7. Defense multiplier MVP
   Implement a simple explicit formula. Recommended:

   attacker_level defaults to 80 unless a level field already exists.
   target_level defaults to 80 unless a level field already exists.

   defense_multiplier = attacker_level_factor / (attacker_level_factor + effective_target_defense)

   Where:
   attacker_level_factor = attacker_level * 10 + 200

   effective_target_defense = max(0, target_defense * (1 - def_reduction) * (1 - def_ignore))

   Keep this function isolated and documented as MVP.

8. Resistance multiplier MVP
   Implement:

   effective_res = target_resistance - resistance_penetration
   resistance_multiplier = 1 - effective_res

   Clamp only if you deliberately decide to; document the decision. Do not silently hide negative resistance behavior if you support it.

9. Crit RNG
   - Preserve `forced_rng.crit` behavior from 001E.
   - If `forced_rng.crit` is absent, use existing RNG context behavior.
   - If `can_crit` is false, crit must never apply.

10. Damage events
   - `damage_dealt` events should include enough metadata for future replay debugging:
     - source_id
     - target_id
     - amount
     - damage_type
     - element
     - is_crit
     - optionally formula_parts / debug object if easy to add
   - Do not break existing event tests.

11. Replay validator

     - at least one buff/debuff modifier
     - a target defense/resistance modifier if your schema supports it cleanly
   - The replay should verify enemy HP after calculated damage.
