Required design principle:
Break damage must be a separate, named pipeline, not mixed into normal `DealDamage` in an opaque way. Future tasks must be able to extend it for super break, DoT, and real elemental effects.

Core requirements:

1. Add break-damage stats
   Extend `Unit` and/or `EffectiveStats` to support at least:
   - `break_effect`, default 0
   - optional `break_damage_bonus`, default 0 through stat_mods

   Buff/debuff `data.stat_mods` should be able to modify:
   - `break_effect`
   - `break_damage_bonus`

2. Add a break damage formula module
   Create a dedicated helper such as `hsr_axis_sim/sim/break_damage.py`.

   Suggested MVP pipeline:

   ```text
   base_break_damage = level_break_base(attacker.level)
   after_element = base_break_damage * element_break_multiplier
   after_toughness = after_element * toughness_factor
   after_break_effect = after_toughness * (1 + break_effect)
   after_break_bonus = after_break_effect * (1 + break_damage_bonus)
   after_defense = after_break_bonus * defense_multiplier
   after_resistance = after_defense * resistance_multiplier
   final_break_damage = after_resistance * (1 + vulnerability)
   ```

   Keep this explicitly documented as MVP.

   You may use a small deterministic level-base formula or lookup table for now, but isolate it in a helper called something like `level_break_base(level)` so it can be replaced later.

3. Element multipliers
   Add an explicit element multiplier helper/table for break damage.

   The exact values can be MVP placeholders, but they must be deterministic, named, documented, and tested. Do not hide magic numbers inline.

   Supported elements:
   - physical
   - fire
   - ice
   - lightning
   - wind
   - quantum
   - imaginary

4. Trigger break damage only when toughness actually breaks
   Existing `DealToughnessDamage` should continue reducing toughness.

   Break damage should only occur when toughness crosses from positive to 0 and `is_broken` becomes true.

   No break damage should occur when:
   - target was already broken
   - attack does no toughness damage because weakness does not match and `ignore_weakness` is false
   - toughness damage does not reduce toughness to 0

5. Add data-driven options to `DealToughnessDamage`
   Extend `DealToughnessDamage` with optional fields such as:
   - `deal_break_damage: bool = false`
   - `break_damage_element: optional string`
   - `break_damage_base_override: optional float` if useful for stable tests
   - `apply_elemental_break_effect: bool = true/false`

   Keep defaults backward compatible: existing toughness tests and replays should still pass without changing their expected HP.

6. Elemental break effect MVP
   When a weakness break occurs, optionally apply a generic debuff/status representing the elemental break effect.

   This MVP should NOT implement full DoT ticking or complicated freeze/imprisonment behavior yet.

   Suggested statuses:
   - `physical_break_bleed`
   - `fire_break_burn`
   - `ice_break_frozen`
   - `lightning_break_shock`
   - `wind_break_wind_shear`
   - `quantum_break_entanglement`
   - `imaginary_break_imprisonment`

   Use existing debuff/status infrastructure:
   - duration_type can be `target_normal_turns`
   - remaining_turns can default to 1 unless you choose a documented MVP value
   - `data` should include metadata like `source`, `element`, and `mvp_no_dot_tick: true`

   Do not add real DoT ticking in this task.

7. Events
   Extend or add events so replay debugging can see break results.

   Existing `weakness_break` event should remain.

   Add useful fields where appropriate:
   - source_id
   - target_id
   - element
   - break_damage_amount
   - elemental_break_effect_id
   - formula_parts if break damage was calculated

   Do not break existing trigger behavior.

8. Replay validator
   Add one new golden replay, for example:

   `hsr_axis_sim/data/golden_replays/break_damage_elemental_mvp.json`

   It should validate at least:
   - toughness goes to 0
   - `is_broken` becomes true
   - enemy HP decreases by expected break damage
   - elemental break debuff exists on target
   - existing break delay still applies if expected fields already support checking it

9. Tests
   Add or update tests covering:
   - break damage only happens on actual break
   - no break damage if weakness does not match and ignore_weakness is false
   - no break damage if target is already broken
   - break_effect increases break damage
   - break_damage_bonus increases break damage
   - defense/resistance/vulnerability affect break damage if you reuse those formula helpers
   - elemental break debuff is applied with expected id/data/duration
   - existing toughness_break_mvp replay still passes unchanged
   - top-level `UnitInstanceSpec.level` override works
