Implementation requirements:

1. Create a source-neutral raw data model.

Add dataclasses in `hsr_axis_sim/adapters/source_models.py` such as:

- `RawExternalCharacter`
- `RawExternalBaseStats`
- `RawExternalSkill`
- `RawExternalTrigger` if useful
- `ImportWarning`
- `ImportReport`

Use the existing project style: dataclasses and explicit `from_dict` methods are preferred unless the project already requires another validation library.

The raw model should be intentionally source-neutral. Do not hard-code Huroka selectors or web page assumptions. Use fields such as:

```json
{
  "source": "external_fixture",
  "source_version": "fixture-001",
  "source_character_id": "fixture_turn_pull_support",
  "normalized_id": "imported_turn_pull_support_mvp",
  "name": "Imported Turn Pull Support MVP",
  "team": "ally",
  "element": "wind",
  "path": "harmony_like",
  "base_stats": { ... },
  "skills": [ ... ],
  "triggers": [ ... ],
  "unparsed_notes": []
}
```

2. Convert raw fixture data into existing normalized schema.

Add functions in `hsr_axis_sim/adapters/external_import.py`:

- `load_raw_external_character(path) -> RawExternalCharacter`
- `normalize_external_character(raw) -> tuple[dict, ImportReport]`
- `write_normalized_character(raw_path, output_path) -> ImportReport`

The normalized output must be compatible with `CharacterSpec.from_dict` and `load_character_spec`.

The importer may initially pass through already-normalized effect specs such as:

```json
{"type": "DealDamage", "amount": 200, "target_ref": "action_targets"}
```

But it must validate effect types through the existing schema validation. Unknown or unsupported raw effects should produce an `ImportWarning` and should not silently create invalid simulator effects.

3. Preserve source metadata without breaking existing loader behavior.

The normalized JSON may include a top-level field such as:

```json
"metadata": {
  "imported_from": "external_fixture",
  "source_version": "fixture-001",
  "source_character_id": "fixture_turn_pull_support",
  "importer_task": "HSR-AXIS-001Q"
}
```

Existing loaders may ignore this field. Do not make the simulator depend on metadata.

4. Add an offline fixture.

Create:

`hsr_axis_sim/data/raw/external_sample/sample_external_character.json`

This fixture should represent one simple support or DPS character. It should include:

- base stats
- basic attack
- skill
- ultimate
- at least one buff or damage effect
- at least one source metadata field

The imported normalized character should be executable by the current simulator.

5. Add tests.

Create `hsr_axis_sim/tests/test_external_import_adapter.py` covering:

- raw fixture loads successfully
- normalization returns a valid normalized character dict
- `CharacterSpec.from_dict(normalized)` succeeds
- writing normalized output to a temp path works
- loading the written normalized JSON with `load_character_spec` works
- a BattleState can be built using the imported character
- at least one action created from an imported skill executes successfully
- unknown raw effect types produce an import warning and do not produce invalid normalized effects
- no existing golden replay is broken

6. Add a small CLI.

`python -m hsr_axis_sim.adapters.external_import --input <raw.json> --output <normalized.json>`

The CLI should print a readable report, including:

- source
- source character id
- normalized id
- number of skills imported
- number of warnings
