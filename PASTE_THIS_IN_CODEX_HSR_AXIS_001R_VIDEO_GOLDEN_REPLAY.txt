Implementation requirements:

1. Manual video trace metadata format

A video-style replay JSON should still be compatible with the existing `ReplayValidator`. Add optional metadata fields that are ignored by the simulator execution but required by the new linter for “video trace” files.

Recommended top-level fields:

```json
{
  "name": "manual_video_trace_sample_mvp",
  "trace_type": "manual_video_trace",
  "source": {
    "platform": "manual_fixture",
    "url": "",
    "video_title": "Synthetic manual video trace sample, not a real video",
    "uploader": "",
    "recorded_by": "Ray/Lumen manual trace protocol",
    "recorded_at": "2026-07-08",
    "notes": "No live video was fetched. This is a protocol fixture."
  },
  "assumptions": [
    "All RNG outcomes are forced in step data where relevant.",
    "Character data uses existing simulator mechanic representative kit."
  ],
  "builds": {
    "carry": {
      "character": "Kill Chain Carry MVP",
      "level": 80,
      "speed": 143,
      "crit_rate": 1.0,
      "crit_dmg": 1.0,
      "notes": "Synthetic build for protocol validation."
    }
  },
  "enemy_setup": {
    "notes": "Synthetic enemies from existing character kit replay."
  },
  "transcription": {
    "step_source": "manual",
    "fields_recorded": [
      "actor",
      "skill_id",
      "target_ids",
      "forced_rng",
      "expected_hp",
      "expected_energy",
      "expected_skill_points",
      "expected_current_av"
    ]
  },
  "tolerance": 0.001,
  "data_sources": { ... },
  "steps": [ ... ]
}
```

Do not require real video URL. Empty URL must be allowed for synthetic fixtures.

2. Add `replay_lint.py`

Create `hsr_axis_sim/sim/replay_lint.py` with functions such as:

- `lint_manual_video_trace(replay_data: dict) -> list[str]`
- `load_and_lint_manual_video_trace(path) -> list[str]`
- CLI: `python -m hsr_axis_sim.sim.replay_lint <replay.json>`

The linter should be strict enough to catch missing metadata but should not execute combat logic. Combat validation remains the job of `ReplayValidator`.

For `trace_type == "manual_video_trace"`, lint should require:

- `name`
- `source`
- `source.platform`
- `source.video_title`
- `source.recorded_by`
- `assumptions` as a list
- `builds` as an object
- `transcription` as an object
- `steps` as a non-empty list
- every step has `step`
- every step has either `skill_id`, `action_id`, or `use_enemy_ai`
- normal steps should have `expected_actor` unless explicitly marked with `allow_missing_expected_actor: true`
- if a step includes `forced_rng`, it must be an object
- if a step includes `expect`, it must be an object

For non-manual-video replay files, the linter may return no issues or a note that the file is not a manual video trace. Do not break existing replay files.

CLI behavior:

```bash
python -m hsr_axis_sim.sim.replay_lint hsr_axis_sim/data/manual_video_traces/samples/manual_video_trace_sample_mvp.json
```

Expected success output should include something like:

```text
PASS manual_video_trace_sample_mvp: manual video trace lint passed.
```

On lint failure, exit nonzero and print every issue.
