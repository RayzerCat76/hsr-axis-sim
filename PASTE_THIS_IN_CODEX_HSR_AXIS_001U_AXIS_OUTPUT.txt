Goal:
Build a human-readable output/report layer for beam search results.

This task should make search results easier to inspect, compare, and export without changing combat mechanics.

Do NOT:
- Do not change action value mechanics.
- Do not change damage formula.
- Do not change buff/debuff duration logic.
- Do not change toughness/break logic.
- Do not change target legality.
- Do not change enemy AI behavior.
- Do not scrape Huroka, Yatta, Bilibili, or any external site.
- Do not build a web UI.
- Do not implement new AI algorithms beyond formatting existing beam search output.

Required implementation:

1. Add a search report module

Create:

```text
hsr_axis_sim/search/report.py
```

It should provide data structures and helpers such as:

```python
SearchReport
AxisStepReport
BeamCandidateReport
build_search_report(result, evaluator=None, top_k=5)
format_axis_markdown(report)
format_axis_text(report)
search_report_to_dict(report)
```

The exact names may vary slightly, but the API must be clear and tested.

2. Report contents

A report should include at least:

- best score
- terminal reason for the best node
- overall terminated reason from the SearchResult
- nodes expanded
- depth reached
- number of final beam candidates
- best axis steps
- final score breakdown if an Evaluator is supplied
- top-K final beam candidate summary

Each axis step should include:

- step number
- actor id
- skill id or action id
- target ids
- global AV before
- global AV after
- SP after
- score after
- human-readable line

Candidate summary should include:

- rank
- score
- depth
- terminal reason
- number of actions
- final global AV
- last action key if available

3. Output formats

Add readable formatting for:

- plain text
- Markdown
- JSON-compatible dict

The Markdown format should be suitable to paste into a project note or future guide.
