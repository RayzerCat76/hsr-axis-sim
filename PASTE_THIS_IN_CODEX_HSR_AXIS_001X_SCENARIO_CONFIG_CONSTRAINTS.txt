Current problem:
The search engine can generate legal actions, but scenario files cannot yet constrain the search space beyond max_depth, beam_width, profile, include_ultimates, max_global_av, and max_nodes_expanded.

For real axis-search work, we need scenario-level constraints such as:
- only allow certain actors to be manually searched
- disable a skill that a player does not want to use
- restrict targets for debugging or reproducing a known axis
- cap branching deterministically for small experiments

Goal:
Add a conservative search-constraints layer to scenario config and search expansion. The constraints should filter already-generated legal choices. They must not bypass existing legality/resource checks and must not mutate loaded skill specs or battle state.

Hard scope boundaries:
- Do NOT change battle timeline semantics.
- Do NOT change damage formula semantics.
- Do NOT change break/toughness semantics.
- Do NOT change buff/debuff duration semantics.
- Do NOT change target legality rules.
- Do NOT change enemy AI pattern semantics.
- Do NOT scrape Huroka, Yatta, Bilibili, or any external website.
- Do NOT implement real character imports.
- Do NOT build a web UI.
- Do NOT add external dependencies.
- Do NOT implement forced-prefix replay scripting in this task unless it is trivial and fully tested. Prefer filtering constraints first.

Recommended architecture:

1. Add a search constraints module, for example:

```text
hsr_axis_sim/search/constraints.py
```

Suggested dataclass:

```python
@dataclass
class SearchConstraints:
    allowed_actor_ids: set[str] | None = None
    disabled_actor_ids: set[str] = field(default_factory=set)
    allowed_skill_ids: set[str] | None = None
    disabled_skill_ids: set[str] = field(default_factory=set)
    allowed_skill_ids_by_actor: dict[str, set[str]] = field(default_factory=dict)
    disabled_skill_ids_by_actor: dict[str, set[str]] = field(default_factory=dict)
    allowed_target_ids: set[str] | None = None
    disabled_target_ids: set[str] = field(default_factory=set)
    max_choices_per_node: int | None = None
```

You may adjust names if the existing code style suggests something cleaner.

Important semantics:
- If an `allowed_*` field is `None`, it means unrestricted.
- If an `allowed_*` field is an empty set, it means allow none.
- `disabled_*` always excludes.
- Actor-level skill allow/disable rules should override or combine clearly with global rules. Recommended: a choice is legal only if it passes all applicable global and per-actor filters.
- Target filtering should apply to every id in `choice.target_ids`. For group targets, the entire target group must pass.

2. Add a function such as:

```python
filter_action_choices(choices: list[ActionChoice], constraints: SearchConstraints | None) -> list[ActionChoice]
```

It should:
- preserve original choice order unless `max_choices_per_node` applies.
- apply actor filters.
- apply skill filters.
- apply target filters.
- apply deterministic branch cap after filtering.

If a branch cap is implemented, either preserve input order or sort by a stable key such as:

```python
(actor_id, skill_id, ",".join(target_ids))
```

Pick one deterministic policy and test it.

3. Integrate constraints into `SearchConfig` / `SearchEngine`.

`SearchConfig` should be able to carry:

```python
constraints: SearchConstraints | None = None
```

In `SearchEngine._expand_next_normal_action(...)`, after `legal_action_choices_for_actor(...)`, apply constraints to the choices.

In `SearchEngine._expand_ultimates(...)`, after `legal_ultimate_choices(...)`, apply constraints too.

Important:
- Enemy AI actions should continue to execute according to enemy AI plans. Do not accidentally block enemies because `allowed_actor_ids` only names allies. If you choose to let constraints apply to enemies too, document it and add tests. Preferred MVP: constraints apply to generated player/search choices, not fixed enemy AI plan execution.

4. Handle no-choice cases clearly.

If constraints filter all choices at a node, the search should not silently loop on the same node forever.

Recommended behavior:
- Return no children from expansion.
- Beam search should preserve a clear terminal reason, such as `no_legal_choices` or `constraints_no_choices`.

If current beam search needs a small adjustment to avoid `children or [node]` hiding this situation, make the minimal change and test it carefully.

Update `hsr_axis_sim/search/scenario.py` so scenario files can include:


Validate types enough that malformed config fails clearly.

8. Add/update tests.

Required tests:
- `SearchConstraints` with no constraints preserves choices.
- disabled actor removes choices for that actor.
- allowed actor permits only that actor.
- disabled skill id removes matching choices.
- per-actor disabled skill id only affects that actor.
- disabled target removes target groups containing that target.
- allowed target permits only target groups fully contained in the allow list.
- `max_choices_per_node` caps choices deterministically.
- scenario config parses constraints.
- constrained scenario CLI runs.
- constrained scenario JSON/Markdown output does not include disabled target/skill in best-axis steps.
- all previous tests still pass.
