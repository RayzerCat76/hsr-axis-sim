Required changes:

1. Add extraction modes

Support at least:

- `batch` mode: preferred default for normal use.
- `per_frame` mode: fallback/debug mode using one ffmpeg call per timestamp.

CLI:

```bash
--extraction-mode batch
--extraction-mode per_frame
```

Default should be `batch`.

2. Implement batch extraction

Use one ffmpeg process for the selected range instead of one process per frame.

Suggested approach:

- Generate expected timestamps using the existing timestamp generation function.
- Run ffmpeg once into a temporary directory with a numeric pattern.
- Use an fps filter derived from interval.
- Rename/copy generated frames to the existing deterministic timestamp names:
  - `frames/t_000.0.jpg`
  - `frames/t_000.5.jpg`
  - etc.

Example direction, not mandatory:

```bash
ffmpeg -hide_banner -loglevel error -nostdin -y \
  -ss <start> \
  -i <video> \
  -t <duration_plus_small_epsilon> \
  -vf fps=<1/interval> \
  -q:v 2 \
  <tmp_dir>/frame_%06d.jpg
```

Then map generated files to expected timestamps.

Important:
- The existing output paths and frame records must remain stable.
- `draft_trace.json` and `frame_index.csv` should still refer to `frames/t_XXX.X.jpg`.
- For start=0, end=16, interval=0.5, expected frame count is 33.

3. Improve per-frame mode

If keeping the current per-frame path, harden it:

- Use `-hide_banner`, `-loglevel error`, `-nostdin`.
- Add `-update 1` when writing a single image to avoid ffmpeg image sequence warnings.
- Add a per-command timeout option.

CLI:

```bash
--ffmpeg-timeout-seconds 30
```
