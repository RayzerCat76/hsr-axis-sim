Task name: Real Trace Timestamp / Frame Anchor Metadata MVP

Codex Reasoning: Medium
Recommended model: GPT-5.6 Terra
Reason: This task is structured metadata, validation, CLI, and tests. It needs reliable software-engineering judgment, but it does not justify the cost and latency of the flagship model.

Context:
HSR-AXIS-002C is accepted. We now have:
- an action-sequence-only real video trace;
- a non-executable semantic placeholder map;
- no numeric combat-state claims.

Source trace:
hsr_axis_sim/data/manual_video_traces/intake/real_video_trace_001_botu_dilemma_floor12_side1_action_sequence_only.json

Semantic map:
hsr_axis_sim/data/manual_video_traces/semantic_maps/real_video_trace_001_botu_dilemma_semantics_v0_1.json

Grounded anchor input:
Use the attached task input:
HSR_AXIS_002D_APPROX_FRAME_ANCHORS_INPUT.json

Important trust boundary:
- Timestamps are MEDIA timestamps from the start of sample1.mov.
- They are not action value, turn time, speed, delay, or any combat number.
- Several boundaries are approximate and must retain confidence metadata.
- Do not invent SP, energy, HP, toughness, damage, targets, RNG, buff values, or action-advance percentages.
- Do not implement real character kits.
- Do not change combat mechanics.

Goal:
Create a separate, non-executable frame-anchor metadata layer that links every prebattle/step action in the accepted real trace to approximate video timestamp ranges and representative extracted frame filenames.

Required data file:
Create:

hsr_axis_sim/data/manual_video_traces/frame_anchors/real_video_trace_001_botu_dilemma_frame_anchors_v0_1.json

Suggested structure:

{
  "frame_anchor_id": "...",
  "source_trace": "...",
  "status": "approximate_media_evidence_only",
  "version": "0.1",
  "timestamp_basis": "seconds_from_local_clip_start",
  "policy": {
    "executable": false,
    "media_timestamps_only": true,
    "combat_numeric_claims_allowed": false,
    "unknowns_allowed": true
  },
  "prebattle": [...],
  "steps": [...]
}

Each anchor record must contain:
- actor
- action
- `step` for normal steps
- time_start_seconds
- time_end_seconds
- representative_frames: list[str]
- confidence: high | medium | low
- notes

Required tooling:
Add a validator/linter, for example:

hsr_axis_sim/tools/trace_frame_anchors.py

It must:
1. Load the action-sequence source trace.
2. Load the frame-anchor file.
3. Verify `source_trace` matches.
4. Verify every prebattle item and every action step has exactly one anchor.
5. Verify actor/action/step keys match the source trace.
6. Verify start/end values are finite nonnegative numbers and start <= end.
7. Verify step start times are nondecreasing.
8. Permit approximate overlaps at boundaries; do not require strict non-overlap.
9. Verify representative frame names are nonempty strings ending in .jpg, .jpeg, .png, or .webp.
10. Verify confidence is high, medium, or low.
11. Reject combat-state fields or claims, including keys such as:
   - av
   - action_value
   - speed
   - sp
   - skill_points
   - energy
   - hp
   - toughness
   - damage
   - crit
   - rng
   - advance_percent
   - delay_percent
12. Print deterministic PASS/FAIL output.

CLI example:

python -m hsr_axis_sim.tools.trace_frame_anchors \
  --trace hsr_axis_sim/data/manual_video_traces/intake/real_video_trace_001_botu_dilemma_floor12_side1_action_sequence_only.json \
  --anchors hsr_axis_sim/data/manual_video_traces/frame_anchors/real_video_trace_001_botu_dilemma_frame_anchors_v0_1.json

Tests:
- valid Botu frame anchors pass;
- missing step anchor fails;
- source trace mismatch fails;
- actor/action mismatch fails;
- reversed timestamp interval fails;
- decreasing step order fails;
- invalid frame filename fails;
- invalid confidence fails;
- forbidden combat-state field fails;
- CLI returns 0 for valid and nonzero for invalid fixtures.
