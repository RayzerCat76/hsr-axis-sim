Goal
====

Create a deterministic, non-executable simulator-binding gap inventory for the accepted first real trace.

The inventory must distinguish:

1. generic engine primitives that already exist;
2. character-specific behavior that is not yet verified or bound;
3. targets or target scopes that remain unknown;
4. missing initial resource and state data;
5. unresolved composite-action behavior;
6. unresolved Mem action-advance semantics;
7. evidence that cannot be recovered from this video alone;
8. the smallest future work items required to move toward an executable replay.

This task is analysis/reporting only. Do not implement real character kits or combat values.

Required implementation
=======================

1. Add a module:

   `hsr_axis_sim/tools/trace_binding_gap_inventory.py`

2. Add a small, explicit assessment input artifact under a new directory such as:

   `hsr_axis_sim/data/manual_video_traces/binding_assessments/`

   Suggested filename:

   `real_video_trace_001_botu_dilemma_binding_assessment_v0_1.json`

3. The assessment artifact must be declarative and evidence-limited. It may classify each prebattle/step item, but it must not add numeric combat values or executable character logic.

4. Add a clear report model. Dataclasses are preferred. The inventory should include at least:

   - inventory ID and version;
   - source evidence report ID/path;
   - explicit non-executable policy flags;
   - global blockers;
   - one prebattle binding assessment;
   - nine ordered step binding assessments;
   - a deduplicated future-work summary.

5. Each step assessment must preserve the accepted source order and include at least:

   - step;
   - actor;
   - action;
   - semantic label/category;
   - current binding status;
   - generic engine primitives already available, if any;
   - missing verified character-kit semantics;
   - target status;
   - missing initialization or resource data;
   - unresolved trigger/composite behavior;
   - evidence limitations;
   - minimum future work items;
   - an explicit `executable_now: false` unless the complete step is genuinely executable from accepted evidence. For this first trace, do not mark a step executable merely because a generic primitive exists.

6. Use a small controlled status vocabulary. Suggested values:

   - `generic_primitive_available`
   - `missing_character_binding`
   - `missing_target_evidence`
   - `missing_initial_state`
   - `unresolved_composite_action`
   - `unresolved_action_advance`
   - `video_insufficient`
   - `blocked`

   You may refine this vocabulary, but keep it explicit and validated.

7. The inventory must explicitly recognize generic capabilities that already exist in the engine where accurate, such as:

   - normal action execution;
   - skill/ultimate action categories;
   - ultimate interrupt windows;
   - generic buffs/debuffs;
   - energy and skill-point resources;
   - generic action advance/immediate action primitives;
   - extra turns and trigger hooks;
   - target legality and action generation;
   - damage/toughness scaffolds.

   Important: acknowledging that a generic primitive exists does not mean the real character action is verified or bound.

8. The inventory must explicitly preserve these unresolved facts:

   - Tingyun ultimate target is unknown in the accepted trace.
   - Pela skill target is unknown.
   - Remembrance Trailblazer skill target/companion state is unknown.
   - Tingyun skill target is unknown.
   - Pela ultimate target scope and resulting debuff values are not validated.
   - Naxia ultimate target and resulting combat state are not validated.
   - `basic_plus_extra_skill` is a composite placeholder, not an executable split.
   - Mem advances Naxia, but the exact amount, timing rule, charge/trigger condition, and binding are unresolved.
   - `skill_plus_extra_skill` is a composite placeholder, not an executable split.
   - initial SP, energy, speed/AV, HP, toughness, buffs/debuffs, enemy state, and RNG are not known from the accepted trace.

9. Validate the assessment against the accepted evidence report:

   - source report ID must match;
   - exactly one assessment for prebattle;
   - exactly nine step assessments;
   - actor/action/step must match the evidence report;
   - no extra or missing steps;
   - list order in the assessment artifact must not determine output order;
   - unsupported status values must fail;
   - `executable_now: true` must fail unless all required blocker lists are empty and the assessment explicitly explains the binding. For this fixture, all items should remain non-executable.

10. Add deterministic Markdown and JSON renderers.

11. Markdown output must include at least:

   - title and source evidence report;
   - strong warning that this is a planning inventory, not a replay;
   - global blockers;
   - compact ordered table;
   - detailed per-step supported primitives, blockers, evidence limitations, and future work;
   - deduplicated minimum-work summary grouped by category.

12. Add a CLI:

```bash
python -m hsr_axis_sim.tools.trace_binding_gap_inventory \
  --evidence-report <accepted-report.json> \
  --assessment <binding-assessment.json> \

```

CLI behavior:

- stdout when `--output` is absent;
- UTF-8 output when present;
- exit 0 on success;

- exit 2 on unreadable/invalid input or runtime/CLI failure;
