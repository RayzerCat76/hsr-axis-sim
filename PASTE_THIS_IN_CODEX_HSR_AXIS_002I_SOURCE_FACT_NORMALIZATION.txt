Goal

Mandatory pre-flight hardening
==============================

1. Atomize compound facts.

The 002H registry contains compound values such as `action_structure` and `action_and_trigger_structure`. Do not carry their verification status into every nested field automatically.

Convert them into atomic normalized records, for example:

```text
tingyun.ultimate.target_type
tingyun.ultimate.energy_cost
tingyun.ultimate.target_energy_restore
tingyun.ultimate.damage_buff_duration
pela.skill.target_type
pela.skill.sp_delta
pela.skill.dispel_count
pela.skill.energy_generation
pela.skill.toughness_value
```

Each atomic fact must have its own:

- normalized field ID;
- value and unit;
- verification status;
- exact provenance references;
- version applicability;
- trace requirement links;
- unresolved notes;
- `simulator_binding_allowed: false`.

A fact may be `corroborated` only when at least two sources actually support that exact atomic field. If only one source supports a subfield, downgrade it to the appropriate controlled status rather than inheriting corroboration from the parent object.

2. Separate Mem timing and Charge semantics.

Create distinct atomic facts for:

- Charge readiness threshold (`100%` if source-backed);
- Charge consumption/cost (`100%` only if directly source-backed);
- Mem immediately taking its own action when Charge becomes ready;
- the selected ally receiving 100% action advance;
- support duration;
- target scope;
- whether self-targeting suppresses the action-advance component, only if sourced and relevant.

Do not conflate:

```text
Mem immediately takes action
```

with:

```text
target ally action advances by 100%
```

If the existing 002H sources do not directly support the Charge-cost field, retain it as missing or partial. Do not infer cost from the readiness threshold.

3. Normalize toughness units without silently converting.

The accepted sources may expose different display conventions for toughness/break values. Every toughness fact must record:

- source-native value;
- source-native unit/convention;
- normalized value only when a documented conversion rule exists;
- otherwise `normalized_value: null` with an explicit ambiguity note.

Do not assume that a source label such as `Break (In-Game) 10` is interchangeable with another site's `Weakness Break 30` without a documented conversion layer.
