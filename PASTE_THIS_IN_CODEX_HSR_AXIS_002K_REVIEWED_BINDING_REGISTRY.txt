Goal
====

Create a small reviewed-binding registry and execution contract before adding a second real action binding.

The registry must make it difficult to:

- execute a raw, unvalidated binding dictionary through the reviewed-binding public API;
- register duplicate binding IDs;
- register a partial shell as a complete skill or complete character kit;
- point a registry entry at an unknown handler or unsupported binding type;
- hide unresolved facts or synthetic-only status;
- accidentally make the real video trace executable.

Do not implement Tingyun Ultimate or any second real action in this task.

Required architecture
=====================

Add a reusable registry under the existing reviewed real-binding namespace, for example:

```text
hsr_axis_sim/real_bindings/registry.py
hsr_axis_sim/real_bindings/registry_v0_1.json
```

Equivalent paths are acceptable if the separation is clear.

The registry must use a validated immutable record/handle rather than exposing raw JSON dictionaries as the normal public execution interface.

Minimum registry metadata per entry
===================================

- registry entry ID
- binding ID
- version
- actor ID
- action category
- binding scope
- binding type, currently only `partial_action_shell`
- binding data path
- handler key
- source atomic-fact artifact path
- accepted atomic-fact artifact SHA-256
- source atomic-fact IDs
- unresolved atomic-fact IDs/fields
- `complete_game_skill`
- `complete_character_kit`
- `synthetic_only`
- `real_trace_executable`
- damage semantics status
- toughness semantics status

For the existing Pela entry, required values include:

```text
complete_game_skill = false
complete_character_kit = false
synthetic_only = true
real_trace_executable = false
damage semantics = not_implemented
toughness semantics = not_implemented
```

Public API
==========

Provide a small typed API similar to:

```text
load_reviewed_binding_registry(...)
list_reviewed_bindings(...)
get_reviewed_binding(binding_id, ...)
execute_reviewed_binding(binding_id, state, target_ids, turn_context=None, ...)
```

Names may differ, but behavior must be equivalent.

Requirements:

1. Loading the registry validates every entry.
2. Getting a binding returns a validated immutable handle or dataclass.
3. Execution is dispatched only through a static allow-listed handler table.
4. The registry must not dynamically import arbitrary module paths from JSON.
5. Execution must validate the underlying binding and atomic-fact artifact before applying effects.
6. Unknown binding IDs and unknown handler keys must fail clearly.
7. A partial binding cannot be requested or registered as a complete skill/kit.
8. Registry execution of the Pela synthetic fixture must match the accepted 002J result exactly.

Registry validation must reject
===============================

- duplicate registry entry IDs;
- duplicate binding IDs;
- missing binding files;
- paths escaping the project/package root;
- unsupported binding types;
- unknown handler keys;
- mismatch between registry metadata and binding JSON;
- mismatch between accepted atomic digest and actual artifact;
- partial bindings claiming `complete_game_skill: true`;
- partial bindings claiming `complete_character_kit: true`;
- `synthetic_only: false` for the current Pela shell;
- `real_trace_executable: true` for the current Pela shell;
- damage or toughness marked implemented for the current Pela shell;
- dangling or unapproved atomic fact IDs;
- mutable registry handles if the chosen model is intended to be immutable.
