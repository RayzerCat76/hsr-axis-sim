Blocking issues
===============

1. Malformed JSON-compatible values can raise uncontrolled `TypeError` from `build_report(...)` before schema validation.

Examples include objects used as:

- `verification_status`;
- provenance `source_id`;
- provenance `release_status`;
- provenance `corroboration_status`;
- `declared_readiness_status`.

2. Fact-specific normalized values are not strictly validated. The current validator accepts invalid claims such as:

- target scope `all_allies`;
- duration `999` or boolean `true`;
- object-valued release scope;
- object-valued unit;
- nonsensical values marked as corroborated magnitude tables or application order.

3. Readiness is misclassified. The current report has:

- `verified_game_equivalence=false`;
- `engine_representation_status=representable_with_source_unverified_same_turn_edge`;
- an explicit same-current-turn duration-edge blocker;

but computes only `blocked_by_source_gap`.

Under the task contract, the current result must be `blocked_by_both` because both source facts and duration semantics remain unresolved.

Goal
====
