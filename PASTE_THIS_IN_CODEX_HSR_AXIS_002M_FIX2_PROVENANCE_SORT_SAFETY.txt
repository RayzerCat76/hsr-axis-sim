Blocking defect
===============

Malformed provenance rows can still trigger raw `TypeError` before the validator reaches its aggregated `ValueError` gate.

Root cause:

- `_validated_provenance(...)` records issues but constructs `FactProvenance` with an unsanitized non-string `field_locator`;
- `_validated_facts(...)` sorts provenance rows using:

  `sorted(provenance, key=lambda item: (item.source_id, item.field_locator))`

- duplicate/equivalent source IDs force Python to compare malformed locator values such as `dict` versus `str`.

Confirmed reproductions
=======================

1. Duplicate valid source ID plus object locator:

```python
p = copy.deepcopy(review["facts"][0]["provenance"][0])
p["locator"] = {"bad": 1}
review["facts"][0]["provenance"][1] = p
build_report(sources, review)
```

Current result:

```text
TypeError: '<' not supported between instances of 'dict' and 'str'
```

2. Two invalid non-string source IDs plus mixed locator types:

Current result:

```text
TypeError: '<' not supported between instances of 'str' and 'dict'
```

Required behavior for both:

- direct `build_report(...)` raises controlled `ValueError`;
- CLI returns validation exit code `1`;
- stderr contains no traceback.

Goal
====

Ensure every malformed JSON-compatible provenance document is validated before sorting, set conversion, comparison, or report construction.

2. Preferred implementation contract:

3. Do not solve this by merely wrapping `sorted(...)` in a broad exception handler. The task requirement is validation before unsafe operations.
