Blocking defect
===============

In:

`hsr_axis_sim/tools/trace_tingyun_ultimate_damage_buff_semantic_readiness.py`

`_claims(...)` currently performs:

```python
if item.get("status") not in STATUSES or item.get("status") != status:
```

before ensuring the raw status is a valid non-empty string.

Consequences:

- status object -> `TypeError: unhashable type: 'dict'`
- status list -> `TypeError: unhashable type: 'list'`
- CLI returns exit 2 instead of the required validation-failure exit 1

Required fix
============

1. Validate the raw status type before any set membership or other hash-based operation.
2. Invalid JSON-compatible status values must be accumulated as validation issues and ultimately raise the normal controlled `ValueError` from `build_report(...)`.
3. Do not solve this by broadly catching `TypeError` around `_claims`, `build_report`, or set membership.
4. Do not weaken the exact status contract for any semantic claim.
5. Preserve deterministic output for valid committed input.

Suggested safe shape
====================

Use an explicit local value and guard, for example conceptually:

```python
raw_status = item.get("status")
if not isinstance(raw_status, str) or not raw_status:
    # `_string` may already have recorded the issue; do not use it in a set.
    pass
elif raw_status not in STATUSES or raw_status != expected_status:
    issues.append(...)
```

The exact implementation may differ, but membership must occur only after the type guard.
